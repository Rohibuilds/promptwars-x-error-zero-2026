System Architecture & Subsystems

Engineered with modular, deterministic components to guarantee correctness and security.

🧭

Deterministic Intent Router

Analyzes user prompts in real time to classify intents into timetable lookups, campus knowledge inquiries, safe arithmetic, or system diagnostics without relying on unpredictable prompt drift.

Subsystem: backend/agent.py
📅

Section-Isolated Timetable Engine

Enforces academic boundaries by indexing class schedules by branch, semester, section ID, and lab batch. Resolves current and next class deterministically based on client time.

Subsystem: backend/timetable_engine.py
🔢

AST-Sandboxed Safe Calculator

Evaluates mathematical formulas using Python Abstract Syntax Trees (AST) with strict whitelists of binary/unary operators, a 40-node ceiling, and exponent magnitude limits. Zero arbitrary code execution (eval).

Subsystem: backend/tools.py
🏢

Grounded Campus Knowledge Store

Provides instantaneous lookups for specialized university facilities, research laboratories, computer centers, and operating hours sourced from validated institutional JSON files.

Subsystem: data/knowledge.json
📦

Isolated Staging Pipeline (Stage 5B)

Automates workbook extraction for 75 first-year sections while strictly walling off unapproved records in isolated staging (data/staging/) with cryptographic SHA-256 provenance tracking.

Subsystem: backend/timetable_staging.py
🛡

Defense-in-Depth Web Security

Features strict Content Security Policy (no inline scripts/styles), sliding-window IP rate limiting (60 req/min), GZip compression, and complete absence of external CDN tracking scripts.

Subsystem: backend/main.py

Operational Capabilities & Limitations

✔ Verified Working Capabilities

  • Provisional Timetable Lookup: Section 1ECE02 registered in production catalog with course and faculty associations.
  • Real-time Next Class Resolution: Computes ongoing or upcoming lecture given section and client timestamp.
  • Interactive Facilities Directory: Real-time keyword search and category filtering across university laboratories and libraries.
  • Autonomous Assistant Chat: Dispatches queries to domain tools with visible execution badges and conversational history.
  • Local Profile Context: Session-persisted student branch and section configuration with live validation.
  • Automated Staging Status: Read-only monitoring of Stage 5B extraction metrics and validation reports.

ℹ Honest Operational Disclosures

  • Production Timetable Scope: Only Section 1ECE02 provisional data is active in production. Weekly period schedules for remaining sections await official administrative release.
  • Staging Dataset Isolation: The 75 sections and 2,682 extracted schedule records in Stage 5B are kept in pending_review status and cannot be served to students until authorized.
  • No External Cloud LLMs: The assistant intentionally does not connect to external third-party paid AI APIs to preserve student privacy and eliminate recurring service costs.
  • In-Memory Rate Limiting: Rate-limiting counters operate in single-process memory; multi-worker cluster deployments require a shared cache (such as Redis).
